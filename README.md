# Rage of Mages 1 / Allods decompilation

Binary-matching decompilation of **Rage of Mages / Allods** (Nival
Entertainment, 1998).

The target is the Russian Buka `Hello__0` engine, whose code is byte-identical
to the English Interplay and Polish releases:

```text
ALLODS.EXE  1,979,392 bytes
SHA-256     5ba821f37356d2da0e1eb907de28b2708714d6e2604b5caef3daf4284b9af7d3
```

The repository mirrors the Gruntz decompilation's layout, command surface,
gates, and one-shell workflow. RoM1 facts are regenerated from `ALLODS.EXE`
and live under `config/retail/`; Gruntz facts never become RoM1 evidence by
inheritance.

## Foundation status

The binary foundation and first matching slice are live:

- 13,023 manually maintained function starts, bootstrapped from independent
  analyzer, FPO, `/GX`, initializer, thunk, and FID evidence;
- 4,384 exact FPO function records, including extents and frame metadata;
- 4,134 exact EH partition rows covering the 66,448-byte terminal `/GX` band,
  147 initializer helpers, and 474 pure IAT thunks;
- 117 MFC runtime classes, 425 proven vtable starts, and 5,772 structured data
  starts with exact companion extents;
- 32,454 recovered DIR32 sites in `config/retail/relocs.tsv`;
- 10,296 addressable ASCII/UTF-16 strings;
- exact PE, section, debug, and 472-import inventories;
- pinned Vostok with the local `--reloc-manifest` recovery path;
- the Gruntz-shaped CLI, Model, Ninja graph, delinker, objdiff integration,
  verification tiers, Ghidra export, semantic navigator, wall diagnostics,
  and permutation infrastructure;
- the selected VC5 SP2 compiler/linker, complete CRT/MFC/ATL headers and
  sources, and hash-pinned static-library archive set;
- 1,354 globally unique exact SP2 CRT/MFC providers promoted from the full
  13,023-start masked FID census, plus context-reviewed `operator delete`,
  `AfxThrowMemoryException`, and `memcpy` identities;
- exact DirectX 5 headers/import libraries and a verified Smacker 3.1L ABI.

The first codec and serde anchors are live: the six-function word-RLE stream
used by save and character files, plus the complete network byte-Huffman core
and its raw 1,024-byte `Packer1.dat`/`Packer2.dat` statistics format. Twenty of
the 21 admitted codec functions are byte-exact; the remaining encoder is
semantically identical at 99.54%, with only VC5 local stack-slot selection in
the residue. Both formats have independent `no_std` Rust implementations and
mapped-retail execution oracles. Word-RLE covers 32,770 fabricated cases per
dimension; byte-Huffman covers 1,024 tied/random tree-and-stream cases plus
4,096 cumulative statistics updates, all with zero disagreements. See the
[format record](docs/format-codecs.md) and manually maintained
[`serde.tsv`](config/retail/serde.tsv) campaign index.

The other exact anchors are seven ordinary Smacker player functions (nine
bodies including `/GX` helpers), the string-led `GetMissionObjectCount` caller
through Bute config reads, and the ordinary `lpDD` BSS datum. The remaining
three admitted Bute bodies are located campaign stubs or near-exact
reconstructions.

VC5 SP2 is the selected compiler. Its `LINK.EXE` is 5.2.0.7132, matching
retail's `5.02` linker stamp, and its complete FPO/archive panel yields 2,180
exact matches: 1,010 bijective and 1,170 retained collisions. The selected
tools and archives are aggregate-hash pinned in `config/compiler.toml`.
SP1 is acquired only if a later representative SP2 compilation witness fails;
the published SP3 package remains a rejected-linker calibration control.

## Requirements

Linux x86_64 with [Nix](https://nixos.org/download) and flakes enabled
(`experimental-features = nix-command flakes`).

## Quickstart

From a fresh clone:

**1. Enter the single development shell.**

```sh
nix develop
```

This provides Vostok, objdiff, Ghidra, LLVM/PDB tools, Wine, the RoM1 CLI,
the exact DirectX 5 SDK, the selected VC5 SP2 environment, and the rejected
SP3 calibration payload. The shell creates and verifies the local Wine prefix
on first entry.

**2. Verify the executable-derived foundation.**

```sh
rom1 tool retail-census
rom1 tool retail-partition
rom1 tool relocs
rom1 tool vendor
rom1 tool compiler-census
rom1 tool fid-census
rom1 tool parity
```

`rom1 tool relocs` checks the tracked manifest; pass `--write` only when
intentionally admitting a reviewed regeneration.

`functions.tsv`, `data.tsv`, and `data_vtables.tsv` follow Gruntz's
manual-census rule. `retail-partition` validates them and regenerates only
companion evidence tables. The explicit `--bootstrap-* --write` modes exist
solely for a new repository's first seed. A reviewed vtable refresh is an
explicit `rom1 verify vtable-scan --write`; scanner-proven rows remain
`unresolved` until reconstructed source earns promotion to `primary`.

**3. Verify the selected compiler and static-library providers.**

```sh
rom1 tool compiler-census
rom1 tool fid-census
```

Both commands verify the active SP2 payload against the tracked executable,
tool, archive, and provider evidence. Compile/link entry points independently
enforce the same hashes; the SP3 bootstrap cannot bypass them.

**4. Run the matching loop after selection and the first TU is admitted.**

```sh
rom1 build                 # cl -> labels -> Model -> delink -> compare -> gates
rom1 match                 # build, then summarize units that changed
rom1 verify status         # current scores and MAX-ledger state
rom1 sema -h               # source/target semantic navigation
```

The objdiff report is written to
`build/objdiff/compare-new/report.json`. Candidate linking is opt-in with
`rom1 link`; it is not part of the normal object-matching loop.

Independent format-codec tests run in the same shell:

```sh
cargo test --manifest-path tools/Cargo.toml --workspace
```

The mapped-retail codec oracles are opt-in; see [`recomp/`](recomp/README.md).

## Pipeline

The target side is derived from the executable and reviewed tables:

```text
ALLODS.EXE + config/retail/*.tsv + source claims
  -> Model -> synthetic PDB -> Vostok -> per-symbol target COFF objects
```

The source side stays the same shape as Gruntz:

```text
edit C/C++ -> exact MSVC compile -> base COFF objects
           -> objdiff against target objects -> verify -> iterate
```

Vostok never guesses from the absent PE relocation directory. Both the Python
model and delinker consume the same reviewed `config/retail/relocs.tsv`.

## Third-party boundaries

RAD Smacker 3.1L is the only currently confirmed non-Microsoft vendor runtime.
The repository preserves the closest public 3.2f headers plus the one-line
version patch and a Clang metadata-only patch (the VC5 path is unchanged), and
verifies all 16 decorated imports against the exact 3.1L DLL. DirectX 5, MFC
4.2, and the CRT are Microsoft platform/toolchain inputs.

Zlib 1.0.4 is deliberately not imported merely because Gruntz uses it. That
candidate came from the RoM2/a2server lineage, not RoM1. The RoM1 executable
lacks zlib identity/error strings; the complete 13,023-start masked FID scan
finds zero matches across 80 substantive signatures and 7,143 controls, while
the older FPO-only probe finds only a
non-bijective generic six-byte `mov eax, <reloc>; ret` shape. See the setup
record and tracked negative controls.

## Formatting

Reconstructed C/C++ uses the same Rust-like clang-format house style as
Gruntz: four-space indentation, attached braces, `int* p`, and braces on every
control body. The tracked pre-commit hook formats staged `src/` and `include/`
files. `vendor/` material is never formatted.
