# Rage of Mages 1 / Allods decompilation

Binary-matching decompilation of **Rage of Mages / Allods** (Nival
Entertainment, 1998).

The target is the Russian Buka `Hello__0` engine, whose code is byte-identical
to the English Interplay and Polish releases:

```text
ALLODS.EXE  1,979,392 bytes
SHA-256     5ba821f37356d2da0e1eb907de28b2708714d6e2604b5caef3daf4284b9af7d3
```

The repository mirrors the Gruntz decompilation's layout, command surface,
gates, and one-shell workflow. RoM1 facts are regenerated from `ALLODS.EXE`
and live under `config/retail/`; Gruntz facts never become RoM1 evidence by
inheritance.

## Foundation status

The pre-source binary foundation is complete:

- 4,384 exact FPO function records, including extents and frame metadata;
- 32,454 recovered DIR32 sites in `config/retail/relocs.tsv`;
- 10,296 addressable ASCII/UTF-16 strings;
- exact PE, section, debug, and 472-import inventories;
- pinned Vostok with the local `--reloc-manifest` recovery path;
- the Gruntz-shaped CLI, Model, Ninja graph, delinker, objdiff integration,
  verification tiers, Ghidra export, semantic navigator, wall diagnostics,
  and permutation infrastructure;
- exact DirectX 5 headers/import libraries and a verified Smacker 3.1L ABI.

The only pre-campaign blocker is the exact VC5 servicing level. Retail's
linker stamp is `5.02`: RTM and SP3 are rejected, while complete SP1 and SP2
payloads are still needed for the deciding compiler/archive census. The
published SP3 package is an **analysis bootstrap**, never an asserted matching
compiler, and compile/link commands fail closed until a winner is recorded in
`config/compiler.toml`.

## Repository layout

```text
scripts/rom1/                the Python package and `rom1` CLI
  core/                      PE, COFF, TSV, path, and relocation primitives
  tool/                      process/tool adapters and evidence censuses
  graph/                     configure + Ninja build/link/match edges
  retail_labels/             source/provider claims over retail censuses
  model.py                   the claims x censuses authority join
  delink/                    synthetic PDB + per-symbol target objects
  compare/                   canonicalize and objdiff base vs target
  verify/                    status/check/bank and tiered negative controls
  sema/                      read-only RVA/xref/string/vtable navigation
  walls/                     residual classification and diagnostics
  ghidra/                    one-way viewer export
  lsp/                       clangd-backed semantic queries and rename
  permute/                   guarded source/TU-state search
config/
  units.toml                 per-TU build manifest and candidate flag profiles
  compiler.toml              fail-closed compiler selection
  retail/                    executable-derived truth, including relocs.tsv
  evidence/                  candidate compiler/library results, never truth
vendor/                      third-party source/includes with provenance
include/                     shared Win32/MFC-era reconstruction headers

nix/patches/                 reviewed local Vostok delinker patches

build/                       all generated local state (gitignored)
```

There is no tracked retail binary. The flake fetches the hash-pinned
`ALLODS.EXE` and `SMACKW32.DLL` from the archived retail CD.

## Requirements

Linux x86_64 with [Nix](https://nixos.org/download) and flakes enabled
(`experimental-features = nix-command flakes`).

## Quickstart

From a fresh clone:

**1. Enter the single development shell.**

```sh
nix develop
```

This provides Vostok, objdiff, Ghidra, LLVM/PDB tools, Wine, the RoM1 CLI,
the exact DirectX 5 SDK, and the published VC5 SP3 analysis bootstrap. The
shell creates and verifies the local Wine prefix on first entry.

**2. Verify the executable-derived foundation.**

```sh
rom1 tool retail-census
rom1 tool relocs
rom1 tool vendor
rom1 tool compiler-census
rom1 tool parity
```

`rom1 tool relocs` checks the tracked manifest; pass `--write` only when
intentionally admitting a reviewed regeneration.

**3. Select the exact compiler once both surviving payloads exist.**

```sh
rom1 tool compiler-census \
  --candidate vc5-sp1=/path/to/sp1 \
  --candidate vc5-sp2=/path/to/sp2 \
  --write
```

Selection requires the complete executable/archive evidence panel. It is not
legal to bypass the unresolved state with the SP3 bootstrap.

**4. Run the matching loop after selection and the first TU is admitted.**

```sh
rom1 build                 # cl -> labels -> Model -> delink -> compare -> gates
rom1 match                 # build, then summarize units that changed
rom1 verify status         # current scores and MAX-ledger state
rom1 sema -h               # source/target semantic navigation
```

The objdiff report is written to
`build/objdiff/compare-new/report.json`. Candidate linking is opt-in with
`rom1 link`; it is not part of the normal object-matching loop.

## Pipeline

The target side is derived from the executable and reviewed tables:

```text
ALLODS.EXE + config/retail/*.tsv + source claims
  -> Model -> synthetic PDB -> Vostok -> per-symbol target COFF objects
```

The source side stays the same shape as Gruntz:

```text
edit C/C++ -> exact MSVC compile -> base COFF objects
           -> objdiff against target objects -> verify -> iterate
```

Vostok never guesses from the absent PE relocation directory. Both the Python
model and delinker consume the same reviewed `config/retail/relocs.tsv`.

## Third-party boundaries

RAD Smacker 3.1L is the only currently confirmed non-Microsoft vendor runtime.
The repository preserves the closest public 3.2f headers plus the one-line
version patch and verifies all 16 decorated imports against the exact 3.1L
DLL. DirectX 5, MFC 4.2, and the CRT are Microsoft platform/toolchain inputs.

Zlib 1.0.4 is deliberately not imported merely because Gruntz uses it: the
RoM1 binary lacks its identifying strings, and the current exact-object probe
finds only the generic six-byte `mov eax, <reloc>; ret` shape. See the setup
record for the negative control.

## Formatting

Reconstructed C/C++ uses the same Rust-like clang-format house style as
Gruntz: four-space indentation, attached braces, `int* p`, and braces on every
control body. The tracked pre-commit hook formats staged `src/` and `include/`
files. `vendor/` material is never formatted.
